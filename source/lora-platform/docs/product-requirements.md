# LoRA 本地工作台 PRD

版本：v1.1 · 文档状态：当前产品基线与验收规范
基线日期：2026-10-08
适用范围：D:\LoRA 本地单人工作台。本文区分已实现、已验收与待接入，不将规划功能写成已完成。
配套材料：docs/technical-plan.md、logs/changes.log、docs/feature-verification-20261008.md。

## 1. 产品目标与使用者

使用者是希望在本机制作、训练和测试 LoRA 的个人创作者。主要问题是环境配置分散、训练日志难查看、自动标签与人工标签混淆、模型和产物路径难管理。
目标：在浏览器完成图片导入、标注、训练配置、CUDA 训练、进度查看、SD + LoRA 对比和模型获取。日常操作不要求打开 Windows PowerShell。
成功标准：一个最小数据集可完成自动打标、人工修订、短训练和产物查看；任务按钮始终给出明确反馈；所有测试结论能追溯到任务、日志或截图。短训练仅验证流程，不代表模型质量达标。

## 2. 范围与信息架构

保留七个页面：总览、数据集、训练配置、任务中心、推理测试、模型中心、全局设置。终端与 SSH 放在全局设置内；任务详情使用右侧抽屉，不增加主导航。
本期范围：修复详情交互；加入容器命令控制与 SSH 输出；展示真实训练损失、状态分布和任务耗时；区分 WD14 自动建议与人工／导入标签；规范界面文案；形成可追溯 PRD。
暂不纳入：多人权限、互联网公开部署、Windows 本机命令执行、交互式 TTY、远程 GPU 训练自动调度和文件同步、SDXL 专属训练参数。SSH 命令连接已接入；远程训练调度仅预留。

## 3. 原理、部署与目录

LoRA 在固定基础模型上训练少量增量权重。训练结果需配合对应基础模型推理；WD14 只为图片生成标签建议，标签需要人工检查。相同 seed 和采样参数可用于基础图与 LoRA 图的流程对比。
部署顺序：检查 Docker Desktop 与 WSL2 → 确认 Docker GPU 可见 → 挂载项目目录 → 启动 API、worker、web → 按需启动独立 ComfyUI → 获取模型 → 导入和标注图片 → 短训练 → 对比推理。
运行拓扑：浏览器 → Nginx web → FastAPI API → SQLite 任务队列 → CUDA worker → sd-scripts。推理任务调用独立 ComfyUI；SSH 从 API 容器连接指定服务器。PowerShell、Bash、Python 在 API 容器执行。
项目根目录：D:\LoRA。宿主 D:\LoRA\data 对应容器 /data。数据集 /data/datasets；模型 /data/models；训练产物和日志 /data/runs；推理图 /data/outputs；状态 data/state；缓存 data/cache；独立 SD 配置 stable-diffusion/user。
Docker Desktop 的全局磁盘仍放 D:\docker；镜像层受全局 Docker 引擎管理，不能声称 LoRA 镜像物理文件全部单独存于 D:\LoRA。LoRA 项目持久数据通过目录挂载归属项目。
启动入口：桌面“启动 LoRA 面板”快捷方式；web 为 http://localhost:8080；独立 SD 为 http://localhost:8188。Windows 启动脚本仅管理 Docker 生命周期和打开浏览器，不承载训练或项目开发环境。

## 4. 主要用户流程

首次使用：双击桌面入口 → 等待服务就绪 → 模型中心检查基础模型与 WD14 模型 → 数据集页选择图片／文件夹导入 → 选择数据集。
标注：运行 WD14 → 任务中心查看日志 → 返回数据集读取最新标签 → 对照自动建议检查训练标签 → 采用 WD14 或保存人工修订。
训练：选择数据集 → 设置步数、Rank、学习率和输出名称 → 开始训练 → 查看日志、步数和损失 → 下载 safetensors。
测试：选择基础模型与 LoRA → 设置提示词、seed 和采样参数 → 提交推理 → 打开结果查看基础模型图与 LoRA 图。
诊断：全局设置选择命令环境与目录 → 执行非交互命令 → 查看输出和退出码 → 必要时停止。SSH 需先获取并确认服务器指纹，再填写本次凭据并连接执行。

## 5. 功能要求与验收条件

### F01 数据集管理

支持系统文件选择窗口导入图片或文件夹；导入后显示图片数、数据集路径、版本和缩略图。导入失败须提示原因，不能只改变按钮状态。
验收：选择一张 PNG 后能在数据集列表和图片编辑区域找到同一图片；数据位于 D:\LoRA\data 内。目录设置弹窗仅浏览已挂载 /data，不能假装可访问未挂载的 Windows 目录。

### F02 WD14 与一般标注

WD14 默认模型为 SmilingWolf/wd-v1-4-convnextv2-tagger-v2，默认阈值 0.35，可配置 0–1。通过复用 sd-scripts 的 ONNX 标注脚本运行。标签建议保存为同名 .wd14.txt；训练仍读取同名 .txt。
来源分为 WD14 自动标签、人工修订、导入标签、未标注。已有 TXT 不得自动认定为 WD14 结果。保存模型 ID、阈值、关联任务和更新时间；自动建议与训练标签分开显示。
没有已有标签时可用 WD14 生成训练 TXT；已有人工或导入 TXT 时保留原文。采用 WD14 标签是明确操作；后续人工保存将来源改为人工修订，同时保留自动建议。
验收：预先保存人工标记，运行 WD14 后人工 TXT 保持不变且自动建议可见；点击采用后 TXT 与建议一致；再次人工保存后来源变为人工修订。

### F03 训练参数与 sd-scripts 后端

配置数据集、基础模型、输出名称、步数、Rank／Alpha、学习率。当前 SD1.5 预设为 FP16、batch 1、gradient checkpointing、latent cache、AdamW8bit。任务 payload 与实际执行参数保持一致。
固定 sd-scripts v0.12.0，提交版本 690ea7f96c23182352ec63def76d431c6120bd2f。本机 RTX 4060 Laptop 8GB 通过 CUDA 执行训练；失败须显示可读原因与进程日志。
验收：短训练任务实际生成非空 safetensors，可查看任务 ID、参数与 stdout。不能用演示文件替代 CUDA 训练产物。训练参数的完整高级配置与多模型架构兼容不在当前预设覆盖范围。

### F04 任务过程与结果

点击“查看过程与结果”立即打开右侧抽屉，包含概况、运行日志、结果、训练曲线。接口未返回时显示加载状态；失败时显示错误并重试，不能无反馈。支持 Esc 关闭、焦点限制与关闭后的焦点恢复。
任务日志显示最近 200 条，支持跟随最新输出；产物提供文件下载与图片预览。训练损失从 sd-scripts 输出解析并持久保存，按实际 step 显示。只有一个采样点时只显示单点。
状态分布标明“当前列表”；耗时仅使用真实开始和结束时间。历史记录缺少结束时间时不推算耗时。抽屉每两秒刷新，主列表每三秒刷新。
验收：已完成推理的结果页显示两张可加载图片；训练结果能下载 safetensors；运行任务能更新日志和进度；失败任务能查看错误；没有数据时有明确空状态。

### F05 SD + LoRA 推理

独立 ComfyUI 可单独启动与使用，并读取统一目录下的模型和 LoRA。平台提交基础模型与 LoRA 对比任务，保留 seed、采样配置和输出路径。
验收：基础图与 LoRA 图均产生文件并在前端显示。视觉差异和模型质量需要更长训练与人工评估，MVP 通过不等于画质通过。

### F06 模型获取与全局设置

模型中心展示 Hugging Face 的基础模型和 WD14 模型条目、可用状态、下载任务与路径。下载由容器执行，缓存和模型落在项目目录；网络失败需显示日志。受限模型的凭据／许可处理、任意平台搜索与通用下载属于后续扩展。
设置面板统一展示模型、数据集、训练、输出目录和默认参数。路径设置必须限定 /data，目录字段有选择弹窗。改变设置后不得仅更新显示而继续使用旧路径；各流程的路径联动须逐项验证。
当前范围说明：目录挂载与默认训练参数已接入；部分训练输出、模型目录及 ComfyUI 输出仍有固定约定。全路径动态迁移与任意基础模型适配属于待完善项，不能声明已完成无缝迁移。

### F07 容器控制台

提供 PowerShell（Linux）、Bash、Python，明确执行位置为 API 容器、工作目录为 /data。命令必须由用户主动提交；返回 stdout、stderr、状态与退出码，支持停止与超时。
前端默认超时 120 秒；后端允许 1–600 秒。最多三个并发会话；单会话输出上限 200000 字符。非交互命令模式不提供完整终端 TTY；API 容器没有训练 worker 的 CUDA Python 环境，不能将其称为 GPU 训练终端。
会话输出暂存在服务内存，服务重启后清除；结束超过十五分钟的记录在下一次创建会话时清理。不能承诺控制台历史已永久保存。
验收：三种环境分别输出实际目录；错误命令显示非零退出码；长命令中途显示输出；停止和超时能结束本地子进程组；/data 外工作目录被拒绝。

### F08 SSH 接口与服务器响应

保存服务器类型、地址、端口、用户名、工作目录和确认过的指纹。密码、私钥、私钥口令仅用于本次连接，不存配置、不写日志。连接时校验指纹后才认证；变化时停止并提示核实。
支持测试登录与连接执行命令，显示服务器 stdout、stderr 和退出码。命令明确运行在 SSH 服务器，不进入本机 GPU 任务队列。停止关闭 SSH 通道，但不能保证远端后台进程终止。
验收：测试服务器通过密码、私钥登录；错误凭据与错误指纹被拒绝；远端命令输出和退出码正确。本期测试使用临时 SSH 协议服务器；AutoDL 实机验收待用户提供连接信息。

## 6. 视觉、文案与交互常项

视觉遵循 Linear 风格：紧凑层级、低饱和背景、细边框、明确主操作。中文和英文嵌入阿里巴巴普惠体 2.0；白天、黑夜、跟随系统三种选项。保持既有信息架构。
图标用于区分数据、标签、训练、终端与结果；图表用于表达真实数据，不做装饰性假指标。标签来源不能只靠颜色区分，必须有文字。
文案使用 skills/product-language/SKILL.md：先说操作或状态，再给必要原因与下一步。不使用“赋能”“一站式”“炼丹”等泛化表达，不把未启用功能写成“可用”。
常项：按钮提交时防重复；等待有加载提示；失败有原因与下一步；空状态说明如何开始；危险停止操作标明对象；弹窗支持键盘操作；移动屏幕上不隐藏必要控制；日志和路径可复制。
默认常量：web 8080、SD 8188、WD14 阈值 0.35、训练分辨率 512、默认步数 100、Rank 16、学习率 0.0001。训练参数可配置；端口和目录映射调整属于部署配置。

## 7. 基本禁止项

禁止将项目模型、数据集、运行缓存和产物下载到 C 盘。
禁止将训练或项目依赖转到 Windows 本机执行；宿主启动脚本仅作 Docker 管理。
禁止覆盖人工／导入标签而不经明确采用操作；禁止给旧 TXT 虚构来源。
禁止伪造进度、损失、GPU 状态、产物或远程连接成功；保留历史演示记录时须标明演示。
禁止持久保存 SSH 密码、私钥或将凭据写入日志／Google 文档。
禁止暴露 Docker socket、挂载宿主系统目录来实现终端；不得将面板直接开放公网。
禁止清理其他项目容器、卷或目录；不可用“架构优化”替代有恢复措施的数据迁移。
禁止将一两步训练宣称为可用成品；禁止隐去未验收与待完善项。

## 8. 约束项与非功能要求

运行约束：Docker Desktop Linux／WSL2 后端；本机 NVIDIA CUDA；单 worker 串行 GPU 队列。ComfyUI 与训练共享显存，打标／训练前释放 ComfyUI 已加载模型。
存储约束：持久数据在 D:\LoRA 内，映射 /data；状态与缓存目录单独挂载；镜像层仍由全局 Docker 存储管理。目录浏览和下载接口校验实际路径，避免路径穿越。
安全约束：端口只绑定 localhost；命令控制是本地可信用户功能，不具备多用户隔离或鉴权。后续公网／多人部署必须先补鉴权、权限和审计。
维护约束：每次改动写 logs/changes.log；真实任务保留 payload、进程日志和产物路径；改动依赖后构建并验证服务健康；备份与回滚路径应明确。
性能与可靠性：页面显示实际状态，指标单位明确；轮询避免同一组件并发请求。构建、短训练、标注、推理、终端和 SSH 均需对应实测证据。资源耗时受机器与模型影响，不承诺固定训练时间。
