# LoRA 工作台文案

先核对代码与验证记录，再写界面或 PRD。区分已实现、已验证、待开发和待用户提供的信息。

- 按钮写动作与对象：开始训练、查看任务、保存标签、测试连接。
- 状态写事实：排队中、正在打标、训练完成、连接失败。不用“赋能”“一站式”“智能炼丹”“真正”“真实”反复宣传。
- 帮助说明先说用户要做什么，再说结果放在哪里。CUDA、sd-scripts 等只放在参数说明和日志来源中。
- 错误说明包含失败原因和可执行的下一步。不要把不明原因的错误一概归为用户输入问题。
- 空状态说明缺什么、下一步做什么；不要捏造数据、曲线、连接状态或效果。
- WD14 输出称“WD14 自动标签”；用户保存称“人工修订”；已有 TXT 来源不明称“导入标签”，不推断模型来源。
- 终端明确执行位置：本机 Windows、API 容器或 SSH 服务器。容器 PowerShell 不称为 Windows PowerShell。
- PRD 的每条需求写条件、行为、异常处理和验收结果。禁止项说明具体禁止行为；约束项说明边界；常项说明全局一致的规则。

交付前删去空泛形容词和重复句，确认每条状态有代码或日志依据，并保留必要限制。
